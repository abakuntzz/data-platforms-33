# ДЗ №1: обёртка над ручной инструкцией

`deploy-hdfs.sh` устанавливает Hadoop на четырёх VM и запускает HDFS.
Для запуска нужны `prepare-node.sh`, параметры среды в `cluster.conf` и шаблоны конфигурации в `hw01-conf/`.
Нужно передавать **всю папку**, не один `.sh`.
В `hadoop-guide.txt` приведён ручной вариант развёртывания со значениями для team-33.
Для другой среды настроить `cluster.conf` и использовать `deploy-hdfs.sh`.

## Параметры среды

Перед передачей файлов на edge отредактировать только `cluster.conf`.
В нём уже указаны значения для team-33. Для другой четвёрки VM заменить:

| Параметр | Значение |
|---|---|
| `EDGE_HOST` | Внешний адрес edge для подключения с компьютера |
| `EDGE_SSH_KEY` | Путь к приватному ключу доступа на edge на компьютере |
| `SSH_USER` | Административный SSH-пользователь, одинаковый на четырёх VM |
| `SSH_KEY` | Путь к ключу доступа на внутренние узлы, уже находящемуся на edge |
| `NAMENODE_HOST`, `DATANODE_0_HOST`, `DATANODE_1_HOST` | Имена или IP для SSH с edge |
| `NAMENODE_IP`, `DATANODE_0_IP`, `DATANODE_1_IP` | Внутренние IPv4-адреса этих же узлов, доступные всем VM |

Каждая пара `HOST` и `IP` должна относиться к одной VM. Пути ключей с пробелами
заключать в кавычки; `$HOME` означает домашний каталог на машине, где читается файл.
В конфигурации хранятся только пути к ключам. Сами приватные ключи в репозиторий не добавлять.
Сервисный пользователь Hadoop остаётся `hadoop`; `SSH_USER` используется для подготовки VM через sudo.

Скрипт подставляет IP в шаблоны `core-site.xml`, `hdfs-site.xml` и `workers`,
собирает `known_hosts` и адрес проверки готовности из этих же параметров.
Готовые конфиги создаются во временном каталоге и копируются на все четыре VM;
исходные шаблоны не изменяются. Не копировать шаблоны с `@...@` в Hadoop вручную.

## Первый запуск

Только чистые ВМ: не должно быть прежнего `/home/hadoop` и данных Hadoop в `/tmp/hadoop-hadoop`.
Схема: edge; NN + SNN + DN на `NAMENODE_HOST`; ещё две DN на `DATANODE_0_HOST` и `DATANODE_1_HOST`.
Ubuntu 24.04 amd64, Java 11, Hadoop 3.4.0.

С компьютера, из папки с файлами развёртывания:

```bash
source ./cluster.conf
ssh -t -i "$EDGE_SSH_KEY" "$SSH_USER@$EDGE_HOST"
```

На edge распаковать файлы в одну папку, перейти в неё и выполнить:

```bash
bash deploy-hdfs.sh --init-hdfs
```

Нужны sudo без пароля, интернет и ключ из `SSH_KEY` на edge.
Host keys внутренних VM у `SSH_USER` должны быть уже проверены для адресов из `*_HOST`.
При первом подключении сверить отпечатки через доверенный доступ;
проверку ключей узлов не отключать. Запускать из обычного интерактивного терминала.
После подготовки каждого узла обёртка запускает `sudo passwd hadoop`: ввести надёжный пароль
и повторить его. Ввод скрыт; пароль не записывается в скрипты и не передаётся аргументом команды.
Для SSH между узлами используются ключи. Обёртка передаёт только их публичные части.
Архив проверяется по [SHA-512 Apache](https://archive.apache.org/dist/hadoop/common/hadoop-3.4.0/hadoop-3.4.0.tar.gz.sha512)
штатной [командой GNU sha512sum](https://www.gnu.org/s/coreutils/manual/html_node/cksum-common-options.html).

Это **одноразовая установка**, не инструмент восстановления. После ошибки не перезапускать
вслепую: часть шагов могла выполниться. Полного автоматического отката нет.
При наличии прежнего `/home/hadoop` или каталога NameNode обёртка остановится без повторного format.

## Проверка результата

После запуска на компьютере, из папки с файлами развёртывания, открыть туннель:

```bash
source ./cluster.conf
ssh -N -i "$EDGE_SSH_KEY" -L "9870:$NAMENODE_IP:9870" "$SSH_USER@$EDGE_HOST"
```

Оставить подключение открытым и перейти в браузере на `http://localhost:9870`.
Ожидаются три live DN без деградировавших узлов. Дополнительно на NN под `SSH_USER`:

```bash
sudo -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -report
sudo -H -u hadoop /usr/lib/jvm/java-11-openjdk-amd64/bin/jps -l
```

В `jps` должны быть NameNode, SecondaryNameNode и DataNode.
После запуска обёртка до 120 секунд ожидает эти процессы на NN, три live DN,
отсутствие dead/stale DN и ошибок дисков, а также выход из Safe Mode.
Если готовность не подтверждена, установка завершается с ненулевым кодом.
Это не откатывает уже выполненные шаги: проверить логи, не повторять `--init-hdfs`.
Для перезапуска использовать команды остановки и запуска из `hadoop-guide.txt`
на узле NameNode, без установки и форматирования.

## Проверка скриптов

На edge, из папки с файлами развёртывания:

```bash
sudo apt-get update
sudo apt-get install -y libxml2-utils
bash tests/test-deploy-hdfs.sh
```

Проверяются синтаксис, XML, вызов passwd на четырёх узлах, запреты повторного format
и отказ при неготовности HDFS; SSH, sudo и скачивание в тестах заменены заглушками.
Отдельный сценарий меняет подсеть, имена узлов, SSH-пользователя и путь ключа;
проверяет сгенерированные XML, `workers`, `known_hosts` и использование параметров в SSH и JMX.
Тесты не устанавливают и не перезапускают Hadoop.
Для подключения к HDFS используются внутренние IP. Данные хранятся в `/home/hadoop/hdfs-hw01/`.
`apt upgrade` всей ОС не выполняется. `prepare-node.sh` сначала создаёт пользователя с заблокированным
паролем, а обёртка сразу задаёт пароль через [passwd](https://manpages.ubuntu.com/manpages/noble/man1/passwd.1.html).

[Документация Hadoop 3.4.0](https://hadoop.apache.org/docs/r3.4.0/hadoop-project-dist/hadoop-common/ClusterSetup.html).
