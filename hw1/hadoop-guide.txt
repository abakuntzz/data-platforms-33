Ручное развёртывание HDFS на четырёх VM

Выполнять блоки последовательно в указанных терминалах. Этот файл — инструкция;
его не нужно запускать целиком как shell-скрипт. Используются те же cluster.conf,
prepare-node.sh и шаблоны hw01-conf/, что и в deploy-hdfs.sh.

Требования: Ubuntu 24.04 amd64, sudo без пароля у SSH_USER на четырёх VM,
доступ к интернету и внутренний SSH-ключ из SSH_KEY на edge.
Установка рассчитана на чистые VM без /home/hadoop и /tmp/hadoop-hadoop.
Для уже установленного кластера использовать только раздел 7 «Перезапуск».
После ошибки сначала проверить её причину; полного автоматического отката нет.

Роли: edge — клиент Hadoop и управление установкой; NAMENODE_HOST — NN, SNN и DN;
DATANODE_0_HOST и DATANODE_1_HOST — ещё два DN. SNN создаёт checkpoints,
автоматическое переключение на резервный NameNode не предусмотрено.
Hadoop 3.4.0; Java 11; сервисный пользователь hadoop.
Все IP, имена узлов, административный пользователь и пути ключей задаются
в cluster.conf. Его исходные значения соответствуют team-33.
Пути ключей с пробелами заключать в кавычки; $HOME относится к машине,
на которой читается cluster.conf. В репозиторий передаются только пути к ключам.

1. Передача файлов и подключение

На компьютере, из папки hw1, настроить cluster.conf и передать всю папку на edge.
При первом SSH-подключении сверить отпечаток узла через доверенный доступ.

```bash
source ./cluster.conf
scp -r -i "$EDGE_SSH_KEY" ../hw1 "$SSH_USER@$EDGE_HOST:"
ssh -t -i "$EDGE_SSH_KEY" "$SSH_USER@$EDGE_HOST"
```

Далее до раздела 6 все блоки выполняются на edge под SSH_USER, в одной сессии Bash.
Команды ssh_node выполняют отдельные операции на внутренних VM без смены
пользователя или рабочего каталога текущего терминала.
Host keys внутренних VM у SSH_USER должны быть уже проверены для адресов *_HOST;
при первом подключении сверить отпечатки через доверенный доступ.
Проверка ключей узлов остаётся включённой.

```bash
cd "$HOME/hw1"
set -euo pipefail
source ./cluster.conf
test "$(id -un)" = "$SSH_USER"
nodes=("$NAMENODE_HOST" "$DATANODE_0_HOST" "$DATANODE_1_HOST")
node_ips=("$NAMENODE_IP" "$DATANODE_0_IP" "$DATANODE_1_IP")
ssh_options=(-i "$SSH_KEY" -o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o UpdateHostKeys=no -o ConnectTimeout=10)

ssh_node() {
    local node=$1
    shift
    ssh "${ssh_options[@]}" "$SSH_USER@$node" "$@"
}
```

2. Подготовка четырёх VM

Сначала проверяется отсутствие прежних каталогов на всех VM. prepare-node.sh
обновляет список пакетов, устанавливает openjdk-11-jdk-headless, wget и
ca-certificates, создаёт hadoop и каталоги .ssh и hdfs-hw01/run с нужными правами.
Обновление всей ОС через apt upgrade не выполняется.

После подготовки каждого узла ввести надёжный пароль hadoop и повторить его.
Ввод passwd скрыт. Для удалённого passwd SSH выделяет терминал.

```bash
sudo -n test ! -e /home/hadoop
sudo -n test ! -e /tmp/hadoop-hadoop
for node in "${nodes[@]}"; do
    ssh_node "$node" 'sudo -n test ! -e /home/hadoop && sudo -n test ! -e /tmp/hadoop-hadoop'
done
bash prepare-node.sh
echo 'Задайте надёжный пароль пользователя hadoop на edge.'
sudo -n passwd hadoop
for node in "${nodes[@]}"; do
    ssh_node "$node" 'bash -se' < prepare-node.sh
    echo "Задайте пароль пользователя hadoop на $node."
    ssh -t "${ssh_options[@]}" "$SSH_USER@$node" 'sudo -n passwd hadoop'
done
```

3. Сервисные SSH-ключи

На edge и NameNode создаются разные ключи hadoop. На три узла с DN добавляются
только публичные части. Приватные ключи остаются на исходных VM.
Host keys для hadoop получаются через уже проверенные административные SSH-соединения.
В конце проверяется вход под hadoop с NameNode на все три DN по внутренним IP.
work_dir — временный каталог; он удалится при завершении этой сессии Bash.

```bash
work_dir=$(mktemp -d /tmp/hdfs-hw01.XXXXXX)
trap 'rm -rf "$work_dir"' EXIT
sudo -n -H -u hadoop ssh-keygen -q -t ed25519 -f /home/hadoop/.ssh/id_ed25519 -N ''
ssh_node "$NAMENODE_HOST" "sudo -n -H -u hadoop ssh-keygen -q -t ed25519 -f /home/hadoop/.ssh/id_ed25519 -N ''"
sudo -n cat /home/hadoop/.ssh/id_ed25519.pub > "$work_dir/authorized_keys"
ssh_node "$NAMENODE_HOST" 'sudo -n cat /home/hadoop/.ssh/id_ed25519.pub' >> "$work_dir/authorized_keys"
for node in "${nodes[@]}"; do
    ssh_node "$node" '
        set -e
        sudo -n tee -a /home/hadoop/.ssh/authorized_keys >/dev/null
        sudo -n chown hadoop:hadoop /home/hadoop/.ssh/authorized_keys
        sudo -n chmod 600 /home/hadoop/.ssh/authorized_keys
    ' < "$work_dir/authorized_keys"
done
: > "$work_dir/known_hosts"
for index in "${!nodes[@]}"; do
    ssh_node "${nodes[$index]}" 'cat /etc/ssh/ssh_host_ed25519_key.pub' | sed "s/^/${nodes[$index]},${node_ips[$index]} /" >> "$work_dir/known_hosts"
done
sudo -n install -o hadoop -g hadoop -m 600 "$work_dir/known_hosts" /home/hadoop/.ssh/known_hosts
ssh_node "$NAMENODE_HOST" '
    set -e
    sudo -n tee /home/hadoop/.ssh/known_hosts >/dev/null
    sudo -n chown hadoop:hadoop /home/hadoop/.ssh/known_hosts
    sudo -n chmod 600 /home/hadoop/.ssh/known_hosts
' < "$work_dir/known_hosts"
printf -v check_ssh_command 'bash -se -- %q %q %q' "${node_ips[@]}"
ssh_node "$NAMENODE_HOST" "$check_ssh_command" <<'CHECK_SSH'
for node in "$@"; do
    sudo -n -H -u hadoop ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 "$node" 'test "$(id -un)" = hadoop'
done
CHECK_SSH
```

4. Архив Hadoop и конфигурация

Подставить IP из cluster.conf в шаблоны, скачать официальный архив и SHA512,
проверить sha512sum -c, распаковать Hadoop и скопировать конфиги на все четыре VM.
Шаблоны с @...@ не устанавливаются напрямую.

Конфиги задают RPC по NAMENODE_IP:9000, Web UI на 9870,
SNN на NAMENODE_IP:9868 и три DN в workers. replication=3.
Данные NN, DN и checkpoints хранятся соответственно в
/home/hadoop/hdfs-hw01/name, data и checkpoint; PID-файлы — в hdfs-hw01/run.
JAVA_HOME и SSH-параметры hadoop берутся из общего шаблона hadoop-env.sh.

```bash
mkdir "$work_dir/conf"
for conf_file in core-site.xml hdfs-site.xml workers; do
    sed -e "s/@NAMENODE_IP@/$NAMENODE_IP/g" \
        -e "s/@DATANODE_0_IP@/$DATANODE_0_IP/g" \
        -e "s/@DATANODE_1_IP@/$DATANODE_1_IP/g" \
        "hw01-conf/$conf_file" > "$work_dir/conf/$conf_file"
done
cp hw01-conf/hadoop-env.sh "$work_dir/conf/"
wget --timeout=30 --tries=3 -P "$work_dir" https://archive.apache.org/dist/hadoop/common/hadoop-3.4.0/hadoop-3.4.0.tar.gz
wget --timeout=30 --tries=3 -P "$work_dir" https://archive.apache.org/dist/hadoop/common/hadoop-3.4.0/hadoop-3.4.0.tar.gz.sha512
(cd "$work_dir" && sha512sum -c hadoop-3.4.0.tar.gz.sha512)
sudo -n install -o hadoop -g hadoop -m 644 "$work_dir/hadoop-3.4.0.tar.gz" /home/hadoop/hadoop-3.4.0.tar.gz
sudo -n -H -u hadoop tar -xzf /home/hadoop/hadoop-3.4.0.tar.gz -C /home/hadoop
sudo -n cp "$work_dir"/conf/* /home/hadoop/hadoop-3.4.0/etc/hadoop/
for node in "${nodes[@]}"; do
    sudo -n -H -u hadoop scp -o BatchMode=yes -o StrictHostKeyChecking=yes /home/hadoop/hadoop-3.4.0.tar.gz "$node:/home/hadoop/"
    ssh_node "$node" 'sudo -n -H -u hadoop tar -xzf /home/hadoop/hadoop-3.4.0.tar.gz -C /home/hadoop'
    sudo -n -H -u hadoop scp -o BatchMode=yes -o StrictHostKeyChecking=yes /home/hadoop/hadoop-3.4.0/etc/hadoop/{core-site.xml,hdfs-site.xml,workers,hadoop-env.sh} "$node:/home/hadoop/hadoop-3.4.0/etc/hadoop/"
done
```

5. Однократная инициализация, запуск и готовность

Этот блок предназначен для нового HDFS. Перед format проверяется отсутствие
каталога метаданных NameNode. Форматирование существующего кластера не выполнять.
start-dfs.sh на NameNode запускает NN, SNN и три DN согласно установленным конфигам.

Проверка готовности ждёт до 120 секунд: на NN должны быть процессы NN/SNN/DN,
в JMX — Live=3, Dead=0, Stale=0, VolumeFailuresTotal=0, Safe Mode должен быть OFF.
При отказе проверить процессы, SSH и логи; повторная установка не является
способом перезапуска или восстановления.

```bash
ssh_node "$NAMENODE_HOST" 'bash -se' <<'START_HDFS'
sudo -n test ! -e /home/hadoop/hdfs-hw01/name
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs namenode -format -nonInteractive
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/sbin/start-dfs.sh
START_HDFS
printf -v check_hdfs_command 'timeout 120 bash -se -- %q' "http://$NAMENODE_IP:9870/jmx?qry=Hadoop:service=NameNode,name=FSNamesystemState"
if ssh_node "$NAMENODE_HOST" "$check_hdfs_command" <<'CHECK_HDFS'
set -euo pipefail
while true; do
    if processes=$(sudo -n -H -u hadoop /usr/lib/jvm/java-11-openjdk-amd64/bin/jps -l) &&
        grep -q ' org.apache.hadoop.hdfs.server.namenode.NameNode$' <<< "$processes" &&
        grep -q ' org.apache.hadoop.hdfs.server.namenode.SecondaryNameNode$' <<< "$processes" &&
        grep -q ' org.apache.hadoop.hdfs.server.datanode.DataNode$' <<< "$processes" &&
        health=$(wget --timeout=5 --tries=1 -qO- "$1") &&
        grep -Eq '"NumLiveDataNodes"[[:space:]]*:[[:space:]]*3([,[:space:]]|$)' <<< "$health" &&
        grep -Eq '"NumDeadDataNodes"[[:space:]]*:[[:space:]]*0([,[:space:]]|$)' <<< "$health" &&
        grep -Eq '"NumStaleDataNodes"[[:space:]]*:[[:space:]]*0([,[:space:]]|$)' <<< "$health" &&
        grep -Eq '"VolumeFailuresTotal"[[:space:]]*:[[:space:]]*0([,[:space:]]|$)' <<< "$health" &&
        safemode=$(sudo -n -H -u hadoop timeout 10 /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -safemode get) &&
        test "$safemode" = 'Safe mode is OFF'; then
        exit 0
    fi
    sleep 3
done
CHECK_HDFS
then
    echo 'HDFS готов: NN, SNN и три live DataNode, Safe Mode выключен. Проверить UI по README.'
else
    echo 'Не удалось подтвердить готовность HDFS за 120 секунд. Проверить процессы, SSH и логи по README; не повторять --init-hdfs.' >&2
    exit 1
fi
```

6. Проверка результата

На edge, в той же сессии, проверить процессы на трёх VM с DN:

```bash
for node in "${nodes[@]}"; do
    ssh_node "$node" 'sudo -n -H -u hadoop /usr/lib/jvm/java-11-openjdk-amd64/bin/jps -l'
done
ssh_node "$NAMENODE_HOST" 'bash -se' <<'VERIFY_HDFS'
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -report
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -safemode get
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfs -ls /
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs fsck /
VERIFY_HDFS
```

Ожидаются NameNode, SecondaryNameNode и DataNode на NAMENODE_HOST;
DataNode на остальных двух VM; три live DN, ноль dead DN, Safe mode is OFF
и HEALTHY. Пустой корневой каталог нового HDFS допустим.
Для диагностики прочитать логи Hadoop на соответствующей VM:

```bash
ssh_node "$NAMENODE_HOST" "sudo -n -H -u hadoop bash -c 'tail -n 80 /home/hadoop/hadoop-3.4.0/logs/*.log'"
```

С компьютера, из папки hw1, в отдельном терминале открыть туннель:

```bash
source ./cluster.conf
ssh -N -i "$EDGE_SSH_KEY" -L "9870:$NAMENODE_IP:9870" "$SSH_USER@$EDGE_HOST"
```

Оставить туннель открытым и перейти на http://localhost:9870.
В разделе Datanodes должны быть три работающих узла без dead/degraded DN.

7. Перезапуск существующего HDFS

С компьютера подключиться к edge по команде SSH из раздела 1.
На edge под SSH_USER, из папки hw1:

```bash
source ./cluster.conf
ssh -i "$SSH_KEY" -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 "$SSH_USER@$NAMENODE_HOST"
```

На NameNode под SSH_USER остановить и запустить HDFS:

```bash
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/sbin/stop-dfs.sh
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/sbin/start-dfs.sh
sudo -n -H -u hadoop /usr/lib/jvm/java-11-openjdk-amd64/bin/jps -l
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -report
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs dfsadmin -safemode get
sudo -n -H -u hadoop /home/hadoop/hadoop-3.4.0/bin/hdfs fsck /
```

Дать DN время зарегистрироваться и повторять проверки до ожидаемых результатов
из раздела 6. При сохранении неготовности через 120 секунд проверить логи.
Форматирование и подготовка пользователей в перезапуск не входят.
